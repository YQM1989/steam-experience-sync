# nxapi 接入复盘

记录时间：2026-10-10。以下区分本项目的真实运行证据、实现选择与未完成范围，不将阶段性失败解释为所有客户端都必须经过人工审批。

## 为什么 Steam 的方式不能直接照搬

Steam 功能主要读取用户公开截图页面，API Key 仅补充游玩时长。Switch 云相册需要 Nintendo 会话以及 Coral App 认证、请求加密和响应解密。改成按按钮执行可以减少请求次数，但不会省去认证步骤。

本机程序向 Nintendo 请求账号与相册数据，媒体从 Nintendo 返回的 CDN 地址下载；nxapi 远程服务参与认证参数生成及相册请求／响应的加解密。当前实测路径仍有这条第三方数据流向。

上游解释了 [Coral 认证](https://github.com/samuelthomas2774/nxapi/blob/47c9d35d9d51d33e62dd6d3733b616e0ad31b02b/README.md#coral-client-authentication) 与 [发布客户端认证方式](https://github.com/samuelthomas2774/nxapi/blob/47c9d35d9d51d33e62dd6d3733b616e0ad31b02b/README.md#nxapi-auth-authentication)。这不是一个给个人桌面程序填入永久 API Key 即可访问的开放相册接口。

## 卡点、证据与最终处理

| 卡点 | 得到的证据 | 最终处理 |
|---|---|---|
| Mac 点击账号按钮无法跳转，应用报 HTTP 400，容易误判为复制操作错误 | Nintendo 会话已取得；失败定位到 `/api/znca/f`，错误为 `incompatible_client` | 把网页授权与相册认证状态分开；保留有效会话，减少无意义的重复登录 |
| 已登记 nxapi OAuth 客户端，配置接口也返回 200，仍不能读取相册 | 旧 `X-znca-Client-Version: 3.0.3` 与请求的 App 3.5.0 不兼容；当时本项目没有取得有效签发标识 | 停止把旧值或 App 版本号当作签发标识；配置检查成功不能报告相册连接成功 |
| 自建认证流程迟迟没有新证据 | 上游文档区分 npm 发布 CLI 与自行构建／库调用的接入方式 | 在隔离目录验证原 npm 发布客户端，而不是继续猜测自建客户端参数 |
| 担心成熟客户端读取过多内容、将令牌写入磁盘 | 相册 CLI 默认会额外读取好友、聊天、服务、活动、公告等资源，存在默认账号缓存和调试日志 | 保留上游协议和发布元数据，用受限预加载适配将账号缓存接到内存，关闭无关读取、日志、`.env` 和更新检查；缓存经管道回传到 macOS 钥匙串 |
| 三项媒体样本下载失败 | 下载器实际返回 `ERR_INVALID_IP_ADDRESS`；Node 的 DNS 回调请求地址数组 | 正确处理 `lookup` 的单地址和 `all: true` 两种形式，保留公网地址校验，不通过关闭安全检查解决 |
| 37 条相册记录与实际附件数量不同 | 5 条是同游戏、同时间、同类型、同内容的重复上传 | 保存 32 份独立媒体，同时保留全部 37 个来源 ID，别名关联已有内容；不同时间的相同画面仍保留 |
| 感想埋在 Markdown 内容里，编辑不方便 | 现有 Obsidian 已启用 Dataview JavaScript | 用独立输入框编辑笔记属性；迁移保留手写文字，支持草稿和冲突处理；未启用能力的仓库保持普通 Markdown |
| 改名后构建仍寻找旧目录 | Rust/Tauri 缓存输出含改名前的绝对路径 | 定向清理相关依赖的 release／debug 构建缓存后重建；保留配置、钥匙串和状态的内部标识 |

## 真正转折的验证

1. 隔离使用 `nxapi@1.6.1-next.257`，从已授权 Nintendo 会话取得真实列表：37 条记录、8 个游戏，各请求阶段成功。由此确认旧认证链失败不等于用户授权无效。
2. 先导入三个不同游戏的样本，核对截图、视频、日期与笔记；成功后导入当前全部列表。
3. 归档后重复执行，新增 0、重复 37，笔记与附件保持；对同一画面的重复上传保留来源别名。
4. 将发布客户端打包进 Tauri 应用。用户只启动一个应用，点击「开始同步」；后台客户端完成后退出，运行锁释放。
5. 真实桌面同步验证保留已有手写感想；更名为 Game Memories 后继续读取原配置、授权及 32 项归档素材。

初始列表为 17 张截图记录、20 段视频记录；去重后为 16 张截图文件、16 段视频文件。两个统计对象不同，不能混写成下载遗漏。

## 接入时应保留的边界

- 不把别的应用的客户端身份复制到自建认证代码；原发布包身份保持不变，本项目通过 `NXAPI_USER_AGENT` 标识调用者。
- 账号模式需先阅读并同意第三方数据流向；Nintendo 官方人工登录使用 PKCE 和回调校验。
- Discord 只曾用于服务网站登录和自建客户端登记；最终发布客户端相册流程不要求启动或登录 Discord，也不运行 Discord presence。
- 凭据不进入 Git、普通设置、笔记、命令参数或错误日志。已归档的媒体与笔记属于本机 Obsidian 内容，不提交仓库。
- 核心、界面、构建、真实账号、桌面按钮和用户审美验收分开记录；测试通过不等于第三方服务安全性或长期稳定性已得到保证。
- nxapi 与预加载适配文件为 AGPL-3.0-or-later。固定源码、许可及适配源码见 [第三方说明](THIRD-PARTY-NOTICES-SWITCH.txt)，不将子进程方式作为免除许可证要求的依据。

## 当前继续使用与排错

已有账号连接正常时直接开始同步，不需要重复登记客户端。失败先看已脱敏的请求阶段和错误代号：会话过期才重新连接；HTTP 429 等冷却结束；协议／兼容失败先核对固定版本与上游资料，避免反复登录或盲目改版本。

新游戏海报目前由用户选择本地图片。已导入游戏的官方海报曾在本机准备，但尚未实现新游戏自动匹配海报。Windows 账号存储、新版 Windows 安装包、跨设备同步和长期增量运行仍需对应环境验证。
